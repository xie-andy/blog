## Motivation

- I was first introduced to the concept of a "second brain" through watching one of Ali Abdaal's videos. The concept is pretty simple. Firstly, suppose you have a limited amount of mental bandwidth/capacity/whatever term you want to use, a pretty reasonable assumption. 

- His argument/my thinking is that the human brain is very good at doing some things (e.g. being creative, working through problems, etc. etc.) and bad at others (e.g. remembering dates, schedules, etc.). 

- From there, given that we have this distinction between different types of mental strain, and one basket can be quite easily solved by tools such as calendars, notes, etc., we should try and reduce our mental load as much as possible by removing these menial requirements and instead freeing up more brain power for more interesting tasks.

- Calendars, note taking tools, and todo lists have all been popular tools to achieve this sort of second brain. Having seen the rise of AI lately, I thought it would be interesting to see if I could build a tool that I can speak to like a human, and have it perform tasks for me and figure out which tool to use, instead of me having to cobble together all these different tools, and use more mental strain to figure out which one to use for which task.

## Idea/Tech stack

- The key part of this assistant is my Mac Mini M4, with 16gb of unified memory. This stays on 24/7 and is what the entire assistant is hosted on.

- Being a personal assistant, obviously the things I say to it will be individual to me, and I don't want to have to worry about my data being farmed by a large AI chatbot. Therefore, a key part of this tech stack will be the use of a local LLM, which means a model that runs on my own computer, rather than using ChatGPT/Claude/Gemini etc.
- Using a local model also means I can make more changes to it later on in this journey, and replace it with newer and better models when they come out or if I upgrade hardware and can build more powerful tools.

- For the database, an SQLite database is used as that is also easily hostable on the Mac, and using a database in the cloud would defeat the whole point of using a local LLM.

- Finally, to make the assistant accessible via mobile, I am using a Flutter iOS application that communicates via Tailscale back to my Mac, and sends it the prompts to execute and receives the responses back.

## Capabilities

- Right now, the capabilities are pretty simple. It has a single skill, which is being able to take notes and also recall them, as well as delete them if I'm no longer interested in the database/personal assistant retaining the note. I wanted to validate that it would work before continuing on with building new skills, which should be quite easy.

- Currently the flow is:
    - Prompt from user (me) -> iOS app -> Tailscale -> Mac Mini -> LLM -> store/retreive/delete from DB -> Tailscale -> iOS app -> response to user.

## What's next

- The very next skill to add will be calendar integration, followed by maps integration. The idea being that I will be able to message it something along the lines of "I have a meeting with x at 1pm at xyz cafe", and it should automatically calculate my commute time, insert into calendar and also pull up any notes on the project that I am working on with that person, or any notes I have. 

- This also means that in the morning, I can get a simple summary of the day to come, and then dump all of my todolist items (things I know I need to do) to it and let it figure out how to organise and schedule everything for me.

- I am aware that there are existing tools to do this - Motion, Reclaim, etc. A key part of future development will be researching what features they implement that are useful, and then copying/adapting them for my specific usecases.

- In the end, (if this project ever reaches an end, because I don't know if it ever will), I will ideally be able to offload all the menial tasks and thinking to this assistant, and then focus on what actually matters and what requires a human to do. There are tons of ways to build this out and I'm really excited to work on this project as an enduring/supporting project alongside everything else.

- Finally, this project should be an excellent way to learn about prompt optimisation and building MCP/RAG capabilities in an efficient manner, as I am limited by the amount of compute I have. I have already started to do some reading about prompt caching and how different models approach storing context in an efficient way.
